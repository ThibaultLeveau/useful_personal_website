## Fresh-database vertical flow

The final images were started behind the same-origin frontend edge with a new PostgreSQL volume.
The isolated database was migrated from empty through `20260802_0004`, role/grant verification
passed, and only a synthetic administrator was bootstrapped. Demo seed was never invoked.

The browser test rotated the one-time password, verified wrong-password handling, protected routing,
missing/forged CSRF rejection, accessibility, logout, and history safety. It then created profile,
settings, two navigation destinations, and a footer column/link through the admin UI. Public API and
About-page assertions proved publication flags, ordering, cache behavior, and private-field
exclusion. Both 320- and 1440-pixel projects passed. Database inspection found all expected
aggregates and zero seed audit events. The exact test project, networks, media volume, and database
volume were removed after evidence collection.

## Corrective loop

Certification found and retested the following material issues rather than suppressing checks:

- PostgreSQL readiness used TCP but needed a longer clean-cluster grace period.
- Public fallback needed bounded route revalidation when the API is unavailable during image build.
- tag invalidation needed immediate expiration and explicit path revalidation.
- Next runtime packaging needed standalone tracing to remove a flaky deploy-time dependency.
- stateful browser tests needed deterministic redirects, exact selectors, and serial execution.
- production frontend responses needed an explicit browser-security-header baseline.
