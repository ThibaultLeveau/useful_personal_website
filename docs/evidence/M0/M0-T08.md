## Delivery

The diagnostic workflow defines independent repository, backend, frontend,
browser, contract, migration, container/security, bootstrap/seed, and aggregate
jobs. Actions and scanner images are immutable, permissions are read-only,
credentials are not persisted, each job is bounded, and scanner or dependency
findings cannot be hidden by the aggregate gate.

## Corrective iterations

1. The migration job originally expected the empty-baseline revision. It now
   captures the single legitimate head, rejects multiple heads, and compares
   the upgraded current revision to that value.
2. The initial image command ignored unfixed findings and retained no structured
   report. Both scans now produce artifacts and every Critical/High finding is
   blocking.
3. The initial frontend job omitted advisory lookup. A blocking production
   dependency audit now precedes frontend compilation and tests.
4. The initial database jobs used one owner/application identity. The required
   privilege job now exercises the accepted bootstrap/migration/runtime split,
   scans its temporary output for synthetic credentials, and always removes its
   exact job-owned resources.

## Decision

The implemented CI structure passes independent local review, including the real
`bootstrap_seed` job delivered in M3. M0-T08 therefore passes locally. No hosted
GitHub Actions run or hosted artifact is claimed; that release-level evidence
remains open and must be captured when a remote repository is available.
