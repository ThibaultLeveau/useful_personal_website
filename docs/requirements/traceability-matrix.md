# Requirements Traceability Matrix

## Update protocol

One row exists per normative requirement in `product-requirements.md`. Update `Delivery status` and `Evidence` at each milestone; do not delete or renumber rows. Allowed delivery states: `Planned`, `In progress`, `Implemented`, `Verified`, `Blocked`, `Deferred`, `Rejected`. `Verified` requires evidence for the linked acceptance criterion. Use durable repository-relative evidence links (test, report, ADR, screenshot, or documentation) plus build/commit where relevant. If scope changes, retain the row and link the change record/ADR.

## Milestone verification summary

At milestone close, add a dated evidence reference to every requirement scheduled for that milestone, record newly discovered defects against the linked AC ID, and roll unresolved `Blocked` items forward explicitly. M20 release validation queries this matrix for all R1 Must rows and must find them `Verified`; target rows require measurement evidence and an explicit disposition.
