# M11 consolidated local gate

Date: 2026-08-04
Environment: Windows development workstation; disposable PostgreSQL database in the local container stack
Scope: M11-T01 through M11-T03, trace milestone M15

## Result

M11 is locally verified. The administrator can create, inspect, rotate, and revoke a named scoped token; plaintext is returned only by create/rotate; bearer authentication is confined to `/api/v1/integrations/*`; and every released integration route requires its exact scope. Production acceptance remains blocked by the owner decisions listed below.

## Automated gate

- Backend format and lint: `ruff format backend` and `ruff check backend` passed; 234 files unchanged and no lint findings.
- Backend typing: `mypy backend/app` passed for 158 source files.
- Backend unit suite: 312 tests passed.
- Frontend lint and type checking: ESLint and TypeScript passed.
- Frontend unit/component suite: 143 tests in 36 files passed.
- Frontend production build: Next.js completed successfully and emitted 25 static pages, including `/admin/api-tokens`.
- Generated OpenAPI/client: the contract exposes 93 paths and the generated client compiles in the frontend gate.
- Database: revision `20260802_0012` is the sole head; upgrade, downgrade to `20260802_0011`, and re-upgrade were exercised against a disposable database.

## Security lifecycle acceptance

A sanitized runtime protocol created a token, called a `content:read` integration route, attempted a `contacts:read` route with insufficient scope, rotated the credential, retried the predecessor, used the replacement, revoked the replacement, and retried it.

| Check | Result |
| --- | --- |
| Valid `content:read` request | 200 |
| Under-scoped contacts request | 401 generic credential failure |
| Rotated predecessor | 401 generic credential failure |
| Replacement before revocation | 200 |
| Revoked replacement | 401 generic credential failure |
| Persisted digest length | 32 bytes |
| Persisted recoverable secret/token columns | None |
| Audit metadata secret matches | 0 |

Unit coverage additionally verifies format/entropy shape, expiry limits, unsupported scope rejection, unknown and malformed credentials, constant-time digest validation path, digest-only projections, one-time response contracts, token-specific rate buckets, and the deny-by-default scope catalog. Browser administrator sessions cannot use bearer tokens, and bearer tokens cannot manage tokens, sessions, passwords, or contact deletion.

## Corrections and independent retest

The first migration metadata traversal attempted to resolve a foreign key owned by the established identity metadata. Registration was corrected to add the API-access tables without sorting across metadata collections. The ORM constraint was then made explicit with `use_alter=True`. A frontend effect lint finding was corrected by loading the inventory through the effect's asynchronous continuation. After those corrections, the complete backend and frontend gates above were rerun and passed.

## Production blockers

Local verification does not choose production policy. Deployment owners must still record the secret-manager source and access policy for the token digest pepper, key-version rotation and rollback ownership, revoked-row retention, external-consumer route/scope approval (including whether `admin:read` gains any route), approved load targets, and an emergency revocation/restore drill. Production configuration rejects the development key version.
